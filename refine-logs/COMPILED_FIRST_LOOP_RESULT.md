# 编译版单核首轮实施与结果

日期：2026-10-23。用户授权范围为“开始实现第一项，同时说明原理和方法”。本轮完成可选Numba单核内核、同源比较入口、数值/溢出验证和方法文档；未开展新多核后端、结构压缩、近似算法或YouTube全源长任务。没有提交或推送。

## 实现与数值语义

- `compiled.py` 使用 `njit(cache=True, nogil=True, fastmath=False)` 编译数值循环，验证存在 nopython 签名。
- BFS、sigma计数和依赖递推保持Brandes定义。用距离标签隐式表达最短路径DAG，反向扫描CSR后继，移除Python前驱列表。
- 工作区一次分配、逐源清空复用：dist/queue为int32，sigma为带逐次溢出检测的int64，delta和总向量为float64。
- 若sigma相加将超出int64，编译阶段返回，原Python任意精度内核重新计算该源。该源依赖仅在成功后提交，因此不会重复计入半个源的贡献。
- 现有全源Python接口与失效接口保留。部分源输出仍为未缩放贡献，不能冒充精确全图介数。
- 这是JIT、数组复用和隐式DAG的组合变体；没有完成把三者独立分离的因素消融。

原理、数学公式、安装、命令和字段解释见[编译版说明](../docs/COMPILED_BRANDES.md)。

- 整例墙钟中位数：Python **105.3452秒**，编译版 **8.0187秒**；逐配对加速比中位数 **14.82倍**，范围10.70—15.58。逐配对比值的中位数与两个墙钟中位数之比不是同一个统计量。
- 新空缓存的首次预热 **1.0885秒**；后两轮从该次缓存预热/加载分别 **0.2802秒、0.4100秒**。这包含分发及小图执行，不等同于纯编译时间；预热已计入整例墙钟。
- 所有配对的1,134,890个节点贡献均满足 `abs(error) <= 1e-8 + 1e-10*abs(reference)`。最大绝对误差 **5.9605e-8**；首对按分母 `max(abs(reference),1)` 的最大相对误差约 **5.11e-14**。大数值处绝对误差可超过atol，需与相对项一起判断，不能仅看atol。
- 整个子进程峰值RSS均约 **303MiB**。共同的CSR校验和导入阶段也在该峰值范围内，本轮峰值RSS没有证明整体内存明显下降，不能将理论工作区节省当作整例RSS实测下降。

本轮完成的是编译单核的首轮验证。原计划中的5次正式比较、独立源集合和多核扩展仍未完成；不能把这三次固定源重复包装为对所有网络、所有起点或所有机器的普遍加速保证。

## 当前边界

YouTube部分源贡献验证覆盖每一个节点，但不是百万源全量计算。原始结果中的 `exact_all_sources=False`、`scaled=False` 不变。

实测加速属于同图、同8源、同顺序的组合实现优化，不能称为多核加速，也不能声称纯JIT单因素收益。内核加速比与整例墙钟加速比必须分别报告。首次编译或缓存加载包含在墙钟里，不藏在未计时阶段。

后续多核扩展、外围树精确压缩和独立源集合确认仍待实施。任何全源耗时换算都是粗估，不能替代长期运行结果；本轮不自动启动过夜/多日全源任务。
