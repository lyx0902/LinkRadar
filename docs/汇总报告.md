## 4. 正确性与完整性核验

2026-11-06 对本次结果执行了只读检查：

1. **覆盖与指纹**：运行 `scripts/audit_snapshot.py`，核验商图及映射、源组计划、有效快照与三个最终数组的 SHA-256，通过；确认 470,164 组、1,134,890 个源点均覆盖，当前代码指纹与运行时记录一致。
2. **全节点数组**：三个数组均为长度 1,134,890 的 `float64`，所有值有限且非负；原图 CSR 与商图的原始 ID 顺序完全一致。
3. **结果恢复**：用最终核心快照再次恢复全原图有序贡献，与保存的 `contributions.npy` 逐项完全一致，最大绝对差为 0。该检查验证恢复过程与保存结果的一致性，两次使用的是同一恢复实现。
4. **分数关系**：全节点核对 `bc_raw = contributions / 2`，以及 `bc_normalized = bc_raw / ((n-1)(n-2)/2)`；两项最大绝对差均为 0。
5. **外围树结构独立核对**：对全部 664,726 个外围节点，依据移除该节点后各分支的节点数，计算不同分支之间的无序节点对数，与其原始介数逐项比较，最大绝对差为 0。直观上，跨不同分支的路径都必须经过该节点；节点自身作为端点的路径不计入介数。
6. **叶节点性质**：原图中 602,539 个度为 1 的节点，其原始介数全部为 0，与叶节点不能作为其他两点之间的路径中间节点一致。

这些检查支持本次结果的完整性、一致性及外围节点数值正确性。**本次没有对 470,164 个核心节点的最终全源结果，用另一套独立算法重新完成全图逐点对照**；哈希通过和同一实现的重复恢复也不能单独证明整个算法不存在系统性错误。浮点计算使用 `float64`，这里的全源精确计算不表示所有数值均为无限精度。

## 6. 结果文件与取用

运行目录 `results/youtube_all_snapshot_8t_2048/` 下：
